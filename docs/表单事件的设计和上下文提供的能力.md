# 表单设计器前端插件事件与上下文注入设计


## 1 表单事件

### 设计目标

前端插件事件分为三个层次：

1. **表单事件**：针对整个表单，例如提交时、任意值变化时。
2. **组件事件**：针对选中的字段组件，例如输入、失焦、清空。
3. **生命周期事件**：针对表单或字段组件的挂载、更新、卸载过程。

三类事件最终使用同一份插件绑定模型和同一个执行器，区别仅在于事件名和传入的事件数据。

完整的事件处理链路为：表单或组件产生事件后，由事件桥接器接收事件并读取对应的插件绑定配置；随后，前端插件执行器为插件注入受控的运行上下文并调用插件入口函数；插件执行结束后，系统根据执行结果完成字段值回写、校验状态更新或显示状态控制。


## 1.1 现在支持的事件

### 1.1.1 表单提交事件 `form.submit`

当前项目已经支持 `trigger: 'submit'`。


执行流程如下：用户提交表单后，系统先通过 Arco Form 完成表单校验，再触发表单提交事件。事件执行器会筛选出已启用且触发类型为“提交”的事件，并按照配置顺序依次执行相应的插件函数。全部插件执行完成后，系统应用插件的出参映射，最后提交处理后的表单数据。

### 1.1.2 表单值变化事件 `form.change`

当前项目已经支持 `trigger: 'change'`。

`useFormEvents` 深度监听表单模型，并使用以下机制控制执行：

- 默认防抖时间为 300ms；
- `isDataLoading=true` 时不触发；
- `runningChangeEvents` 防止插件出参回写造成递归执行；
- 使用表单快照跳过值未变化的更新；
- 组件卸载时清理定时器。

### 1.1.3 组件输入事件 `component.input`

当前 `showItem.vue` 会深度监听组件描述对象中的字段值。当新值与旧值不一致，并且表单不处于数据加载状态时，系统会调用现有的输入事件处理方法 `inputItem()`。

现有 `inputItem()` 会：

1. 使用 `eval` 执行 `comDes.method.input`；
2. 在非设计态调用 `provideDesigner.filterData(comDes)`。

因此当前组件输入事件已经存在，但还是“字段脚本”模式，并未统一接入前端插件函数。

### 1.1.4 字段联动事件

字段值变化后，运行态的 `filterData` 能继续触发：

- `form[fieldId]` 同步；
- 表达式计算；
- 下拉选项刷新；
- 跨表单联动；
- 字段校验；
- 字段显示控制；
- `formLogics` 重新计算。

该能力不是独立插件事件，但属于组件事件执行后的核心副作用链。

### 1.1.5 插件调试事件

`FormEventManager.vue` 和插件设计器已支持：

- 加载已发布插件；
- 选择前端插件函数；
- 解析入参和出参；
- 输入调试参数；
- 执行插件入口函数；
- 展示日志和 JSON 结果；
- 超时控制。

当前前端函数可以接收触发配置，以及设置字段显示状态、字段值和字段错误信息的能力。此外，工具集合中预留了调用后端服务的能力。

其中 `setFieldVisible` 还是空实现，`callBackend` 当前会直接抛错。

## 1.2 可添加事件

参考界面把事件分为“组件事件”和“生命周期”。建议使用带命名空间的事件名，防止表单事件与组件事件重名。

### 1.2.1 推荐事件枚举


| 参考界面事件 | 建议事件名 | 作用域 |
| --- | --- | --- |
| 输入值时 | `component.input` | 当前组件 |
| 值修改时 | `component.change` | 当前组件 |
| 获取焦点时 | `component.focus` | 当前组件 |
| 失去焦点时 | `component.blur` | 当前组件 |
| 点击清空按钮时 | `component.clear` | 当前组件 |
| 挂载前 | `form.beforeMount` / `component.beforeMount` | 全部组件 / 本组件 |
| 挂载完成（全部组件） | `form.mounted` | 全表单 |
| 挂载完成（本组件） | `component.mounted` | 当前组件 |
| 更新前 | `form.beforeUpdate` / `component.beforeUpdate` | 全表单 / 当前组件 |
| 更新完成 | `form.updated` / `component.updated` | 全表单 / 当前组件 |
| 卸载前 | `form.beforeUnmount` / `component.beforeUnmount` | 全表单 / 当前组件 |
| 卸载完成 | `form.unmounted` / `component.unmounted` | 全表单 / 当前组件 |
| 错误捕获 | `form.error` | 全表单 |

### 1.2.3 事件数据

插件函数除了运行上下文外，还应收到一份标准事件数据。该数据必须包含事件名称、表单标识和事件发生时间；在具体场景下，还可以包含字段标识、组件类型、当前值、修改前的值、原生浏览器事件以及错误信息。通过统一事件数据结构，不同类型的插件可以采用一致的方式识别事件来源和读取事件内容。


## 2 上下文能力

### 当前上下文

项目当前使用字符串作为依赖注入键。其中，`provideDesigner` 提供设置组件属性、读取组件属性、执行字段联动和设置校验规则等能力；`isDataLoading` 用于表示表单当前是否正在加载数据；`formModel` 用于提供表单模型。



## 2.1 函数调用

### 2.1.1 定义类型化注入键


建议为表单插件运行上下文定义统一的类型化注入键。运行上下文需要包含当前运行模式、表单标识、只读表单模型和数据加载状态。运行模式应明确区分设计态、预览态和运行态。

上下文还应提供以下几类能力：

1. **表单数据读取**：读取完整表单数据，以及按字段标识读取单个字段值。
2. **字段数据修改**：按字段标识异步设置字段值。
3. **字段属性控制**：读取或修改字段属性，以及控制字段的显示和禁用状态。
4. **字段校验控制**：主动校验字段、设置字段错误信息和清除字段错误信息。
5. **插件事件执行**：接收插件事件绑定配置和标准事件数据，调用对应的插件并返回执行结果。

类型化注入键可使用名为 `form-plugin-runtime` 的唯一标识创建，并将其与统一的运行上下文类型关联。

这里使用 `InjectionKey` 而不是字符串键，可以统一所有消费组件的类型。



### 2.1.2 动态前端插件执行器

动态前端插件执行器应向插件注入一份受控上下文，具体包括：

1. **事件信息**：以只读方式提供本次触发的标准事件数据。
2. **触发配置**：以只读方式提供当前事件绑定中的触发参数。
3. **表单能力**：允许插件读取当前表单的完整数据，但不能直接修改原始表单对象。
4. **字段能力**：允许插件读取和设置字段值、读取和局部更新字段属性、控制字段显示或禁用、设置或清除错误信息，以及主动触发字段校验。
5. **工具能力**：允许插件根据表达式和可选的数据集合执行受控计算。

上述写操作中的字段值修改、属性修改、显示状态控制、禁用状态控制和主动校验均应采用异步方式，以便执行器等待相关副作用处理完成。通过只暴露明确允许的能力，可以避免插件直接访问或修改设计器内部状态。



### 2.1.3 插件作者的函数写法

在线编写插件函数时，插件作者通过执行器传入的上下文读取和操作表单。例如，在学生信息联动场景中，插件先读取 `studentId` 字段。如果该字段没有值，则为其设置“请先填写学生编号”的错误提示并结束执行；如果已有值，则清除原错误信息，根据学生编号生成学生名称，将生成的名称写入 `studentName` 字段，并确保该字段处于显示状态。执行结束时，插件可以返回更新后的学生名称，供出参映射或后续流程使用。

同一个插件函数也可以根据事件名称执行不同逻辑。例如，当事件为 `component.focus` 时，插件可以把当前字段的占位提示修改为“正在输入……”；当事件为 `component.clear` 时，插件可以将关联字段 `relatedField` 的值清空。通过这种方式，一个插件入口可以响应多种组件事件，同时保持各事件处理逻辑相互独立。
