# 旧版浏览器兼容实施方案

> 制定日期：2026-09-21  
> 范围：DMP `/wornbench/` 与警官端 `/workflow/`，两端同步实施。  
> 本文是实施方案；当前阶段不修改业务代码。

## 1. 目标与边界

- 以两个工程 `vite.config.ts` 已配置的 Chrome 79+、Edge 79+ 为最低目标；首先覆盖表单数据、原始数据及报表筛选，再扩展到其他业务页面。
- 保持数据、交互和权限行为不变。兼容降级允许减少装饰效果，不允许隐藏数据、让按钮重叠或阻断操作。
- 不把 IE 11 纳入本轮目标；若现场存在更低版本或定制内核，先取得实际浏览器版本和复现页面，再单独评估。
- 开发服务器不能作为旧浏览器验收依据；以生产构建产物和实际目标浏览器验证。

## 2. 现状与风险

| 位置 | 当前情况 | 风险与处理方向 |
| --- | --- | --- |
| 两端 `vite.config.ts` | 已使用 `@vitejs/plugin-legacy`，目标为 Chrome/Edge 79+；Monaco worker 已有 `RegExp d` 兼容转换 | 保留现有配置，核验生产产物、worker 和动态加载；不要误以为 JS 转译能处理 CSS 兼容 |
| `src/views/application/components/OriginalDataPanel.vue` | 操作列已用相邻链接 `margin-left: 12px` 替代 `gap`；普通文本列使用 Arco 表格 `ellipsis`/`tooltip` | 在目标浏览器确认省略号、提示层、固定列和列拖拽正常；附件/签名/子表格不能因截断失去交互 |
| 同一组件的子表格样式 | 存在五处 `:has()` 选择器 | 旧内核会忽略这些规则；改为渲染时添加明确类名，由类选择器控制行高、分隔线和内边距 |
| 其余样式 | DMP `src` 中约 149 个样式文件使用 `gap`，约 10 个文件使用 `:has()`；需逐处区分 flex/grid 与业务影响 | 优先处理按钮、工具栏、表格和弹窗；为不支持 flex `gap` 的场景使用相邻元素外边距或父容器内边距。不能仅凭 `@supports (gap: ...)` 判断 flex gap 是否可用 |
| 运行时 API | 少量代码使用较新的 API，例如 `Array.prototype.at` | 逐项确认最低浏览器支持；必要时局部改写或按需 polyfill，不默认加入全量 polyfill |

## 3. 实施步骤

### 阶段一：建立可复现基线

1. 记录现场浏览器完整版本、系统、缩放比例、分辨率及失败页面。分别保存表单数据、原始数据、报表筛选的截图与控制台错误。
2. 两端分别运行 `vue-tsc`、单元测试和生产构建，记录当前结果；确认 legacy 脚本与样式文件实际进入发布包。
3. 对 `gap`、`:has()`、较新 JS API、worker 和第三方组件做清单，按“功能阻断 / 布局错乱 / 仅装饰差异”排序。

### 阶段二：修复当前页面的确定性问题

1. 在原始数据表格的子表格单元格上添加专用类名，用该类替换 `:has()`；保留多行内容的分隔线与可点击附件。
2. 对表格操作列继续使用相邻元素外边距，核对两按钮与三按钮场景；工具栏和筛选弹窗中实际出现贴合的 flex 布局再加同类回退，不全局覆盖 Arco 的 `a-space`。
3. 验证省略号只作用于文本列；悬停能显示完整文本，空值、长中文、长英文/URL、多值字段、固定操作列和调整列宽后均正常。
4. 验证报表筛选切换条件后清空旧值且只发起一次列表刷新；空值条件移除、`IS_NULL`/`IS_NOT_NULL` 保留、其他筛选条件不丢失。

### 阶段三：扩展全项目兼容

1. 按清单逐个替换会影响业务的 `:has()`；优先显式类名，必要时由 Vue 状态设置类名，避免依赖 DOM 结构猜测状态。
2. 对需要旧版 flex 布局的 `gap` 使用局部回退。统一采用无 `gap` 的间距方案或精确特性检测；避免 `gap` 与 `margin` 同时生效造成双倍间距。
3. 检查新 JS API、Web Worker、Monaco、富文本编辑器、图表和第三方表格。仅在确认缺失时加入局部替代或 polyfill，避免增大全部页面包体。
4. 将兼容约束写入代码审查清单：新增 `:has()`、flex `gap`、新 JS API 或新依赖时必须注明最低浏览器验证结果。

### 阶段四：双端验证与发布

1. 两端分别执行 `npx vue-tsc --noEmit -p tsconfig.app.json`、`npm test`、`npm run build`；测试生产包，不只测试 Vite 开发模式。
2. 使用实际 Chrome/Edge 79～89 环境验证登录、表单数据、原始数据、筛选、修改/删除、报表设计与展示；再用当前浏览器做对照。
3. 重点检查水平滚动、固定列、拖拽列宽、tooltip 定位、弹窗遮挡、按钮间距、子表格多行和控制台异常。
4. DMP 与警官端按各自路由和业务差异分别验收，不通过整文件覆盖同步；记录每端修改文件与结果。

## 4. 验收标准

- 目标浏览器可以打开生产包，无阻断性脚本错误；Monaco/worker 页面不因不支持的语法中断。
- 表单数据、原始数据长文本保持单行省略，悬停可读取完整内容；附件、签名和子表格仍可正常操作。
- 操作按钮和核心工具栏在不支持 flex `gap` 的浏览器中仍有稳定间距，不重叠、不出现双倍间距。
- 报表筛选切换条件后旧值清空，关联表格刷新一次，发送的条件与当前界面一致。
- 两端类型检查、单元测试、生产构建通过；旧版和当前浏览器的关键流程回归通过。

## 5. 待确认信息

实施前最好取得现场浏览器版本与一处可复现页面。如果实际版本低于配置目标，先调整支持边界与技术方案，再承诺兼容范围。
