# 浏览器版本过低对系统的影响说明

> 编制日期：2026-09-21  
> 适用系统：DMP `/wornbench/`、警官端 `/workflow/`  
> 当前最低适配目标：Chrome 79+、Chromium Edge 79+

## 1. 说明

本系统基于 Vue 3、Vite、Arco Design Vue、Monaco Editor、ECharts 等现代前端技术构建。两个工程已经通过 `@vitejs/plugin-legacy` 生成兼容代码，并针对旧版 Chromium 的 Monaco 正则表达式问题做了专项处理，但构建兼容不能覆盖所有浏览器差异，尤其不能自动修复 CSS 能力、浏览器内核缺陷和第三方组件的运行环境要求。

使用低于 Chrome/Edge 79 的浏览器、IE、旧版国产浏览器兼容模式或长期未升级的定制 Chromium 内核时，系统可能无法正常运行。即使页面可以打开，也不代表全部业务功能可用。

## 2. 影响等级

| 等级 | 表现 | 业务影响 |
| --- | --- | --- |
| 严重 | 白屏、脚本加载失败、登录循环、页面持续报错 | 系统不可用，无法进入或完成业务 |
| 高 | 保存、提交、审批、筛选、上传、预览等操作无响应 | 数据可能未提交或流程无法继续 |
| 中 | 表格错位、按钮重叠、弹窗超出屏幕、内容无法完整查看 | 容易误操作，部分功能可绕行 |
| 低 | 圆角、阴影、间距、动画等视觉效果异常 | 不阻断业务，但影响使用体验 |

## 3. 具体影响

### 3.1 系统加载与登录

- 浏览器无法解析生产脚本时，可能出现白屏、加载动画不结束或控制台语法错误。
- 动态模块、Promise、网络请求或存储能力异常时，可能出现登录后跳回登录页、路由无法切换或配置加载失败。
- 旧浏览器缓存机制不一致，发布新版本后可能继续使用旧入口或旧静态资源，造成页面与接口版本不匹配。HTML 中的禁止缓存标签只能降低入口页缓存概率，最终仍应由服务器响应头控制缓存。
- 过旧浏览器通常已经停止安全更新，存在账号、令牌和业务数据泄露风险。

### 3.2 表单设计、填写与校验

- 拖拽、复制栅格、组件配置和富文本编辑器可能失效或报错。
- 日期、人员、部门、下拉选择和地址等复杂组件可能无法展开、无法回填或显示错误。
- CSS 布局能力不足时，栅格间距、字段排列和按钮位置可能异常；页面显示正常但点击区域可能已经偏移。
- 校验、联动表达式或动态脚本执行异常时，可能出现必填校验不生效、字段显隐错误或提交数据不完整。

### 3.3 表单数据与原始数据

- 不支持 flex `gap` 时，修改、删除等操作按钮可能贴在一起；工具栏按钮和筛选项也可能缺少间距。
- 不支持 `:has()` 等选择器时，子表格的行高、分隔线和内边距可能失效。
- 文本省略、悬停提示、固定列、水平滚动和拖拽列宽可能异常，导致长内容遮挡其他列或无法查看完整值。
- 批量选择、分页、排序、字段显示、导入和导出可能出现点击无响应或状态与界面不同步。

### 3.4 报表设计与展示

- 数据表列宽拖拽可能跳跃、失效或无法保存；设计页和展示页宽度可能不一致。
- 筛选条件切换后列表可能不刷新，或界面条件与发送给接口的条件不一致。
- ECharts、画布缩放、图表 ResizeObserver 等能力受限时，图表可能空白、尺寸错误或窗口变化后不重绘。
- 大数据量表格在旧内核中的渲染性能较差，容易出现明显卡顿或浏览器无响应。

### 3.5 审批、流程与任务操作

- 提交、通过、拒绝、转交、退回等按钮可能无响应，或请求已完成但页面状态没有更新。
- 流程图、审批记录、变更记录和详情抽屉可能渲染失败或错位。
- 用户重复点击未及时更新的按钮，可能触发重复请求，并出现“任务已被处理”等提示。

### 3.6 文件、图片及 URL 预览

- 上传组件、分片处理、Blob 下载或新窗口打开可能受浏览器策略限制。
- Monaco、富文本、PDF/Office 预览或 Web Worker 可能加载失败。
- URL iframe 预览可能因旧版安全策略、跨域限制或目标网站拒绝嵌入而空白；这类问题不能全部通过前端兼容解决。
- 全屏、退出全屏、弹窗高度和内部滚动可能表现不同，尤其在小分辨率和旧版内核中容易出现留白或双滚动条。

## 4. 浏览器范围建议

| 浏览器环境 | 建议 | 支持结论 |
| --- | --- | --- |
| 最新稳定版 Chrome / Chromium Edge | 推荐 | 完整回归的首选环境 |
| Chrome / Chromium Edge 79～89 | 有条件支持 | 需使用生产兼容构建，并完成关键业务回归 |
| 低于 79 的 Chromium 内核 | 不建议 | 未纳入当前构建目标，功能与安全风险较高 |
| IE 及旧 EdgeHTML Edge | 不支持 | Vue 3、Vite 及主要依赖不以该环境为目标 |
| 国产浏览器极速模式 | 视实际 Chromium 版本 | 版本达到最低目标后仍需现场验证 |
| 国产浏览器兼容模式 | 不支持或高风险 | 通常使用 IE 内核，可能无法加载系统 |
| 移动端内置 WebView | 需专项验证 | 内核版本、文件能力、全屏与下载策略差异较大 |

## 5. 对用户的建议

1. 优先使用单位允许范围内的最新版 Chrome 或 Chromium Edge，并保持自动更新。
2. 国产浏览器请选择“极速模式”，不要使用“兼容模式”；同时记录浏览器名称、版本和内核版本。
3. 页面异常时先保存尚未提交的数据，再刷新页面；不要连续点击提交、审批或删除按钮。
4. 报障时提供页面地址、发生时间、浏览器完整版本、系统版本、截图及控制台错误。
5. 发布后若仍显示旧页面，可清理该站点缓存并重新打开；服务端仍需正确配置 HTML 不缓存、带哈希静态资源长期缓存。

## 6. 对运维与研发的建议

- 在登录页或系统入口检测浏览器版本，对低于支持范围的环境给出明确提示，但不要仅依赖 User-Agent 阻断正常用户。
- 生产环境使用响应头控制入口 HTML 缓存；JS/CSS 文件名带内容哈希并允许长期缓存，避免所有资源完全禁用缓存带来的性能问题。
- 兼容验证必须基于生产构建，不以 Vite 开发环境结果代替。
- 新增 `:has()`、flex `gap`、较新 JavaScript API、Worker 或第三方依赖时，应检查最低浏览器支持情况并提供局部降级。
- 两端每次同步修改后分别执行类型检查、单元测试、生产构建和目标浏览器关键流程回归。

## 7. 结论

浏览器版本过低不仅会造成样式差异，还可能影响登录、数据提交、审批、筛选、文件处理和报表展示的正确性。当前系统以 Chrome/Edge 79+ 为最低目标，推荐使用最新稳定版。低于该范围的环境不应作为正式生产操作终端；如业务必须支持，应先明确具体浏览器内核和版本，再进行专项改造与验收。
