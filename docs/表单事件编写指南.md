# 表单事件编写指南

本文档对应当前表单设计器的“表单事件”代码运行时，说明事件支持的能力、代码写法、数据结构，以及子表单等特殊组件的处理方式。

> 最后核对日期：2026-08-03。若运行时接口发生变化，应同步更新本文档和新建事件的默认代码模板。

## 1. 表单事件是什么

表单事件允许在表单填写过程中执行一段异步 JavaScript。当前支持两种触发方式：

| 触发方式 | 触发时机 | 适用场景 |
| --- | --- | --- |
| 表单提交 `submit` | 用户点击提交后、表单校验和提交请求之前 | 跨字段校验、提交前补充数据、统一处理子表单 |
| 字段变化 `change` | 绑定字段的值发生变化后，默认防抖约 300ms | 字段联动、动态显隐、动态调整必填状态 |

同一触发方式配置多个事件时，事件按照配置列表顺序逐个执行，前一个事件执行完成后才会执行下一个事件。

字段变化事件按 `formData` 中发生变化的字段 ID 精确匹配。数据初始化期间不会触发字段变化事件，事件脚本引起的值回写也有递归执行保护。

## 2. 基本写法

事件代码运行在异步函数中，因此可以直接使用 `await`，不需要再包一层函数。

```js
const sourceFieldId = 'sourceFieldId';
const targetFieldId = 'targetFieldId';
const value = formData[sourceFieldId];

if (!value) {
  return { error: '请先填写来源字段' };
}

formData[targetFieldId] = value;
return { result: 'ok' };
```

注意：

- 可以使用 `const`、`let`、条件判断、循环、数组方法、对象方法和 `await`。
- 不需要也不能使用 `export`。
- 不要在代码最外层再声明同名的 `formData`、`fields`、`rules` 或 `formApi`。
- 推荐始终使用字段 ID 访问数据，不要使用字段标题。字段标题可能重复或被修改。
- 可在事件弹窗右侧的“字段 ID”面板中搜索、复制或插入字段 ID。

## 3. 可用上下文

### 3.1 `formData`

`formData` 是当前填写态的响应式表单数据，键为字段 ID。

```js
// 读取
const name = formData['nameFieldId'];

// 写入
formData['resultFieldId'] = '处理结果';

// 清空。推荐写入与组件匹配的空值，不建议仅 delete
formData['textFieldId'] = '';
formData['multipleFieldId'] = [];
formData['objectFieldId'] = {};
```

事件执行结束后，运行时会把 `formData` 中与字段 ID 同名的值同步到对应字段的 `props.value`。

### 3.2 `fields`

`fields` 是当前表单的原始响应式组件树，即 `formList`。常见字段结构如下：

```js
{
  id: 'fieldId',
  title: '字段名称',
  type: 'INPUT',
  showItem: false, // false 表示显示，true 表示隐藏
  props: {
    value: '',
    required: true,
    disabled: false,
    readonly: false
  },
  children: [], // 布局或子表单模板字段
  list: []      // 子表单实际数据行
}
```

一般场景优先使用 `formApi`，只有处理子表单实际行或运行时未封装的字段属性时才直接操作 `fields`。

### 3.3 `rules`

`rules` 是 Arco Form 当前使用的响应式校验规则对象，键为实际字段 ID，值为规则数组。

```js
rules['fieldId'] = [
  { required: true, message: '该字段不能为空' },
  { match: /^1\d{10}$/, message: '手机号格式不正确' },
];
```

推荐通过 `formApi` 修改规则，以统一处理单个规则对象和规则数组。

### 3.4 `formApi`

`formApi` 提供字段查找、显示状态和校验规则控制能力。字段查找会递归遍历普通布局的 `children` 和子表单的 `list`。

## 4. `formApi` 完整说明

### 4.1 获取字段

```js
const field = formApi.getField('fieldId');
if (!field) {
  return { error: '未找到指定字段' };
}
```

找不到字段时返回 `undefined`。如果组件树中存在重复 ID，则返回递归遍历时遇到的第一个字段。

### 4.2 显示字段

```js
const success = formApi.showField('fieldId');
```

找到并显示字段时返回 `true`，找不到时返回 `false`。

### 4.3 隐藏字段

```js
formApi.hideField('fieldId');
```

隐藏只改变显示状态，不会清空字段值。需要清空时应显式赋空值：

```js
formApi.hideField('fieldId');
formData['fieldId'] = '';
```

### 4.4 按条件设置显示状态

```js
const shouldShow = formData['switchFieldId'] === true;
formApi.setFieldVisible('targetFieldId', shouldShow);
```

第二个参数为 `true` 时显示，为 `false` 时隐藏。

### 4.5 获取字段规则

```js
const currentRules = formApi.getFieldRules('fieldId');
```

没有规则时返回空数组。

### 4.6 覆盖字段规则

```js
formApi.setFieldRules('fieldId', [
  { required: true, message: '请输入内容' },
  { match: /^[a-zA-Z0-9]+$/, message: '只能输入字母和数字' },
]);
```

也可以传入单个规则对象：

```js
formApi.setFieldRules('fieldId', {
  required: true,
  message: '请输入内容',
});
```

该方法会覆盖字段的全部现有规则。如果只想补充规则，应使用 `addFieldRule`。

### 4.7 追加字段规则

```js
formApi.addFieldRule('fieldId', {
  validator(value, callback) {
    if (value === '禁止值') callback('不能填写“禁止值”');
  },
});
```

### 4.8 清空字段规则

```js
formApi.clearFieldRules('fieldId');
```

该方法删除运行态规则，但不会自动修改组件设计配置中的 `props.required`。如果需要同时取消必填标识，应使用 `setFieldRequired`。

### 4.9 修改必填状态

```js
// 设置为必填
formApi.setFieldRequired('fieldId', true, '请填写该字段');

// 取消必填
formApi.setFieldRequired('fieldId', false);
```

该方法会同时修改组件的 `props.required` 和 `rules`。取消必填时会保留原有格式校验，只把已有规则中的 `required: true` 改为 `required: false`。

## 5. 返回值和错误处理

### 5.1 正常完成

```js
return { result: 'ok' };
```

返回内容目前只用于调试，不会自动映射到字段，也不会自动提交给后端。字段值应直接写入 `formData`。

### 5.2 业务错误

```js
return { error: '业务校验未通过' };
```

返回对象中存在非空 `error` 时，运行时会抛出错误。提交事件失败后会中止后续校验和提交；字段变化事件失败会记录到浏览器控制台。

### 5.3 主动抛出异常

```js
throw new Error('处理失败');
```

适用于不可恢复的异常。普通业务校验更推荐返回 `{ error: '...' }`。

## 6. 异步请求和接口调用

事件代码支持浏览器原生 `fetch` 和 `await`：

```js
const response = await fetch('/your-api/path', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ id: formData['sourceFieldId'] }),
});

if (!response.ok) {
  return { error: `接口请求失败：${response.status}` };
}

const data = await response.json();
formData['targetFieldId'] = data.value;
```

当前限制：

- `src/api` 目录中的 TypeScript 函数没有注入事件上下文，不能直接写 `import`，也不能直接调用诸如 `getUserList()` 之类的模块函数。
- 若接口依赖项目 Axios 拦截器、签名或特殊鉴权，应先由开发侧把受控请求能力注入运行时；不要在事件代码中复制敏感令牌。
- 运行时没有内置请求超时和取消机制。复杂请求建议使用 `AbortController`。
- 事件脚本拥有浏览器上下文能力，应只允许可信的表单设计者编辑。

## 7. 常用组件值结构

事件阶段读取到的是组件填写态数据，提交前还没有执行后端数据格式转换。

| 组件类型 | 事件阶段常见值 | 注意事项 |
| --- | --- | --- |
| 单行/多行文本、邮箱、网址 | `string` | 清空使用 `''` |
| 数字、金额、评分 | `number` 或空值 | 不要用字符串拼接代替数值计算 |
| 开关 | `boolean` 或组件配置的开关值 | 判断时优先使用严格比较 |
| 多选、复选 | `array` | 清空使用 `[]` |
| 人员、部门（单选） | 通常是包含人员/部门对象的数组 | 提交时会转换为单个 ID |
| 人员、部门（多选） | 人员/部门对象数组 | 提交时会转换为 ID 数组 |
| 日期区间 | `{ start, end }` 或组件当前格式 | 不要当作普通字符串拆分 |
| 时间区间 | `{ start, end }` | 提交时会按组件格式标准化 |
| 地址 | `{ prov, city, dist, det }` | 应整体替换或逐项维护完整结构 |
| 定位 | `{ address, longitude, latitude, ... }` | 经纬度和地址应保持一致 |
| 附件、图片、签名 | 文件对象数组或组件定义的数据结构 | 不要只保留展示 URL，避免丢失文件标识 |
| JSON Schema | 普通对象 | `formApi` 只能控制外层组件，内部字段由 JSON Schema 自身逻辑管理 |
| 关联数据 | 对象或对象数组 | 事件阶段保留关联记录结构，提交时会进一步转换 |

修改对象或数组时，推荐创建新值，便于响应式系统识别：

```js
formData['addressFieldId'] = {
  ...formData['addressFieldId'],
  city: '北京市',
};

formData['multipleFieldId'] = [
  ...(formData['multipleFieldId'] || []),
  newItem,
];
```

## 8. 子表单处理

### 8.1 子表单为什么需要特殊处理

子表单同时存在三类标识：

1. 子表单组件自身 ID；
2. `children` 中的模板字段 ID，通常形如 `子表单ID.子字段ID`；
3. `list` 中每一行的实际字段 ID。新增行会生成不同的运行态 ID，而字段的 `field` 属性仍保留模板字段 ID。

事件执行发生在提交数据转换之前。子表单最终提交的行对象数组由 `subform.list` 中每个单元格的 `props.value` 生成。因此，处理全部行时应以子表单组件的 `list` 为准，不应只依赖 `formData[subformId]`。

此外，`formApi.getField(templateFieldId)` 会返回递归遍历遇到的第一个同 ID 字段，通常是 `children` 中的模板字段，不一定是第一行实际字段。

### 8.2 通用递归查找辅助函数

```js
function findFieldInTree(list, fieldId) {
  if (!Array.isArray(list)) return undefined;

  for (const field of list) {
    if (String(field?.id || field?.props?.field || '') === String(fieldId)) {
      return field;
    }

    const child = findFieldInTree(field?.children, fieldId);
    if (child) return child;

    if (Array.isArray(field?.list)) {
      for (const row of field.list) {
        const rowField = findFieldInTree(Array.isArray(row) ? row : [row], fieldId);
        if (rowField) return rowField;
      }
    }
  }

  return undefined;
}
```

查找子表单组件：

```js
const subform = findFieldInTree(fields, 'subformId');
if (!subform || !Array.isArray(subform.list)) {
  return { error: '未找到子表单' };
}
```

### 8.3 把子表单读取为行对象数组

```js
function getCellFieldId(cell) {
  return String(cell?.field || cell?.props?.field || cell?.id || '');
}

const rows = subform.list.map(row => Object.fromEntries(
  row.map(cell => [getCellFieldId(cell), cell?.props?.value]),
));

console.log(rows);
```

这里生成的键使用模板字段 ID，结构接近最终提交数据，但人员、部门、时间等组件仍是填写态值，尚未执行提交转换。

### 8.4 更新指定行的单元格

```js
const rowIndex = 0;
const childFieldId = 'subformId.childFieldId';
const row = subform.list[rowIndex];
const cell = row?.find(item => getCellFieldId(item) === childFieldId);

if (!cell) {
  return { error: '未找到子表单单元格' };
}

const newValue = '新的值';
cell.props.value = newValue;

// 同步填写态模型，便于规则校验和后续脚本读取。
formData[cell.id] = newValue;
```

不要只写 `formData[subformId]`，因为最终提交转换读取的是每个实际行字段的 `props.value`。

### 8.5 批量处理每一行

```js
const sourceChildId = 'subformId.sourceFieldId';
const targetChildId = 'subformId.targetFieldId';

for (const row of subform.list) {
  const sourceCell = row.find(cell => getCellFieldId(cell) === sourceChildId);
  const targetCell = row.find(cell => getCellFieldId(cell) === targetChildId);
  if (!sourceCell || !targetCell) continue;

  const nextValue = String(sourceCell.props.value || '').trim();
  targetCell.props.value = nextValue;
  formData[targetCell.id] = nextValue;
}
```

### 8.6 控制子表单行字段显示和校验

对子表单实际行，推荐直接操作行字段，并使用实际行字段 ID 设置规则：

```js
for (const row of subform.list) {
  const cell = row.find(item => getCellFieldId(item) === 'subformId.childFieldId');
  if (!cell) continue;

  // showItem 为 false 表示显示，true 表示隐藏。
  cell.showItem = true;

  formApi.setFieldRules(cell.id, [
    { required: true, message: '该行字段不能为空' },
  ]);
}
```

如果需要同时修改必填星号：

```js
cell.props.required = true;
formApi.setFieldRules(cell.id, [
  { required: true, message: '该行字段不能为空' },
]);
```

不建议对子表单实际行直接使用模板字段 ID 调用 `showField`、`hideField` 或 `setFieldRequired`，因为模板字段和首行字段可能存在 ID 冲突。

### 8.7 子表单字段变化事件限制

字段变化事件按实际 `formData` 键精确匹配，而新增子表单行会生成新的运行态字段 ID。设计时选择的通常是模板字段 ID，因此它不能保证匹配所有动态新增行。

当前建议：

- 需要处理全部子表单行时，优先使用“表单提交”事件；
- 字段变化事件只适合明确知道实际字段 ID 的场景；
- 不要通过事件脚本直接增删 `subform.list`，当前运行时没有封装行增删、规则初始化和组件生命周期同步能力。

## 9. 其他特殊组件

### 9.1 栅格布局、标题、分割线和按钮

这些组件通常没有可提交值：

- 可以在已知组件 ID 时通过 `showField`、`hideField` 控制外层显示；
- 不应为它们设置表单校验规则；
- 右侧字段 ID 面板主要展示有数据值的组件，因此这些纯布局/展示组件可能不会出现在面板中。

### 9.2 人员和部门组件

事件阶段不要假设单选值就是字符串 ID。建议兼容对象数组：

```js
const selected = formData['userFieldId'];
const userId = Array.isArray(selected) ? selected[0]?.id : selected?.id || selected;
```

写入时应保持组件需要的完整对象结构；只写 ID 可能导致组件无法正确显示名称。

### 9.3 日期和时间区间

```js
formData['dateIntervalFieldId'] = {
  start: '2026-08-01',
  end: '2026-08-31',
};

formData['timeIntervalFieldId'] = {
  start: '09:00:00',
  end: '18:00:00',
};
```

具体格式应与组件的 `props.format` 保持一致。

### 9.4 地址和定位

地址和定位均应按对象处理，不要只替换其中一个展示字符串。修改后保留原有其他属性：

```js
const oldLocation = formData['locationFieldId'] || {};
formData['locationFieldId'] = {
  ...oldLocation,
  address: '新的地址',
  longitude: 116.397,
  latitude: 39.908,
};
```

### 9.5 上传、图片和签名

这些组件的值通常包含文件 ID、文件名、下载地址和上传状态等信息。事件脚本应复制完整文件对象，不要自行构造只有 URL 的简化对象。

```js
formData['targetAttachFieldId'] = [
  ...(formData['sourceAttachFieldId'] || []),
];
```

### 9.6 JSON Schema 业务组件

JSON Schema 外层字段值是一个对象：

```js
formData['jsonSchemaFieldId'] = {
  ...(formData['jsonSchemaFieldId'] || {}),
  studentName: '张三',
};
```

当前 `formApi` 只能控制 JSON Schema 外层组件的显示、必填和外层规则，不能通过内部字段 key 控制其内部模块或字段。内部显隐、校验和模块联动应使用 JSON Schema 组件自身的逻辑配置。

### 9.7 关联数据组件

关联数据在事件阶段通常是原始关联记录对象或数组，提交时才会执行选项值、人员部门和附件等字段转换。修改时应保留记录的完整结构，避免只留下显示文本。

## 10. 动态规则示例

### 10.1 根据开关动态必填和显示

```js
const enabled = formData['switchFieldId'] === true;

formApi.setFieldVisible('targetFieldId', enabled);
formApi.setFieldRequired('targetFieldId', enabled, '启用后必须填写该字段');

if (!enabled) {
  formData['targetFieldId'] = '';
}

return { result: 'ok' };
```

### 10.2 跨字段日期校验

```js
const start = formData['startDateFieldId'];
const end = formData['endDateFieldId'];

if (start && end && new Date(start).getTime() > new Date(end).getTime()) {
  return { error: '结束日期不能早于开始日期' };
}

return { result: 'ok' };
```

### 10.3 自定义字段校验器

```js
formApi.setFieldRules('scoreFieldId', [
  { required: true, message: '请输入分数' },
  {
    validator(value, callback) {
      const score = Number(value);
      if (!Number.isFinite(score) || score < 0 || score > 100) {
        callback('分数必须在 0 到 100 之间');
      }
    },
  },
]);
```

## 11. 调试建议

1. 在事件编辑弹窗右侧确认字段名称和字段 ID。
2. 字段变化事件选择绑定字段后，点击“调试预览”并修改该字段。
3. 表单提交事件点击“调试预览”后，在预览底部点击“提交”。
4. 使用 `console.log(formData)`、`console.log(fields)` 查看当前填写态数据和组件树。
5. 子表单问题优先打印目标子表单的 `children`、`list` 和行字段的 `id/field/props.value`。
6. 调试完成后删除不必要的日志，避免在正式环境输出敏感信息。

## 12. 当前能力边界

当前表单事件运行时支持：

- 读取和修改表单数据；
- 查找字段；
- 控制普通字段和外层组件显示/隐藏；
- 获取、覆盖、追加和清空字段规则；
- 动态修改必填状态；
- 执行异步 JavaScript 和浏览器原生请求；
- 通过原始组件树处理子表单实际行。

当前没有提供以下受控 API：

- 直接导入或调用 `src/api` 模块函数；
- 子表单行的新增、删除和排序；
- 聚焦、滚动到字段或主动触发表单校验；
- 设置字段级错误提示或清除已有校验状态；
- 控制字段禁用、只读和选项数据的专用方法；
- JSON Schema 内部字段和模块控制；
- 事务回滚。脚本执行到一半抛错时，之前已经完成的响应式修改不会自动恢复。

如需扩展上述能力，应优先在 `FormEventApi` 中增加明确、可测试的接口，不建议让事件代码直接依赖页面组件实例或 DOM。
